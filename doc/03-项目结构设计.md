# 03 · 项目结构设计

> 需求 §2。技术栈采用推荐方案：**Tauri 2 + Vue 3 + TypeScript + Rust 核心**。

## 2. 各模块职责

| 路径 | 职责 | 关键接口 |
|------|------|----------|
| `src-tauri/src/activity.rs` | 启动 rdev 监听线程；每次事件更新 `last_activity_at`；判断空闲 | `start_listener()`、`on_activity()` |
| `src-tauri/src/state.rs` | 维护 `UserState`（Idle/Working/Resting）、今日工作/休息片段、喝水记录 | `tick()`、`reset_daily()` |
| `src-tauri/src/scheduler.rs` | 周期性 tick 检查阈值，触发休息/喝水提醒事件 | `run_scheduler()` |
| `src-tauri/src/storage.rs` | 读写 `%APPDATA%/rest-reminder/<date>.json` | `load()`, `save()`, `append_water()` |
| `src-tauri/src/tray.rs` | 创建托盘图标 + 菜单（暂停/恢复、设置、退出） | `build_tray()` |
| `src-tauri/src/commands.rs` | 暴露给前端的 Tauri 命令（获取设置、保存设置、获取今日数据、记录喝水） | `#[tauri::command]` 函数 |
| `src/stores/appStore.ts` | 前端单一数据源，通过 `invoke` 与 Rust 同步 | `loadSettings()`, `saveSettings()` |

## 3. 前后端数据流

```
[用户键鼠] → activity.rs(rdev) → state.rs(更新时间戳/状态)
                                      │
                                      ├─ scheduler.rs(每秒 tick)
                                      │     ├─ 达到工作时长 → emit "rest_reminder"
                                      │     └─ 达到喝水间隔 → emit "water_reminder"
                                      │
                                      ├─ storage.rs(持久化)
                                      │
                                      └─ Tauri 事件 → 前端 appStore → Dashboard/弹窗
前端设置变更 → invoke command → commands.rs → storage.rs(保存) + state.rs(热更新)
```

---

## 4. 设计原则

- **Rust 持有真相（source of truth）**：所有计时与状态在 Rust 端，前端只做展示与配置，避免 WebView 休眠导致计时不准。
- **低耦合**：活动检测、状态、调度、存储四层互不依赖 UI。
- **可测试**：`state.rs` / `scheduler.rs` 纯逻辑可单测（见 §08）。
