# 09 · 代码审查标准与流程

> 目的：把"代码质量参差不齐"从靠个人自觉，变成可落地的标准 + 流程 + 自动门禁。
> 配套文件：`.github/PULL_REQUEST_TEMPLATE.md`（PR 自检清单）、`.github/workflows/ci.yml`（自动质量门禁）。
> 适用范围：本仓库（Tauri 2 + Vue 3 + Rust 绿色桌面应用）。

---

## 0. 设计原则

- **审查是教学，不是门禁**：好的审查意见要解释"为什么"，让作者下次自己就能避坑。
- **标准要具体、可执行、可量化**：每条都能对应到一个可勾选的动作或一条命令。
- **严重级别统一语言**：🔴 blocker（必须修）/ 🟡 suggestion（应该修）/ 💭 nit（可选）。
- **机器兜底，人聚焦判断**：格式化、clippy、类型检查、单测交给 CI；人工审查聚焦正确性、设计、安全性。

---

## 1. 角色与职责

| 角色 | 职责 |
|------|------|
| **Author（作者）** | 自审、写 PR 描述、本地跑通检查、响应审查意见、及时修订 |
| **Reviewer（审查者）** | ≥ 1 人；对照 §4 清单逐条确认；给出带级别的评论 |
| **Maintainer（维护者）** | 保护 `main` 分支、合并、裁决争议、回收 issue |

> 当前为单人开发：至少做到"隔一段时间自查 + 强制 CI 绿灯 + 合并前过一遍 §4 清单"，避免带病合入。

---

## 2. 分支与提交规范

- **分支策略**：`main` 受保护；功能开 `feature/xxx`；修复开 `fix/xxx`；线上紧急开 `hotfix/xxx`。
- **合并方式**：`squash merge`，保持 `main` 线性、单 PR 单提交。
- **提交信息**：采用 Conventional Commits：`feat / fix / docs / refactor / test / chore` 前缀 + 简短动宾。
  - 例：`fix(rust): 避免 State 临时值跨语句借用导致 E0716`
- **禁止入库**：`node_modules/`、`dist/`、`src-tauri/target/`、`gen/schemas/`（已在 `.gitignore`）；密钥、证书、`.env` 永不入库。

---

## 3. PR 流程（强制）

1. **规模控制**：单 PR 有效改动 ≤ 400 行；超出必须拆分（降低审查负担、缩小回归面）。
2. **PR 描述**：填 `PULL_REQUEST_TEMPLATE.md` —— 改动摘要、关联 issue、自测记录、UI 变更截图。
3. **质量门禁**：CI 全绿（`cargo fmt --check` + `cargo clippy -D warnings` + `cargo test` + `npm run type-check` + `npm run build`）是合并硬前提。
4. **审查门槛**：≥ 1 个 approved review（或单人项目自查确认 §4 全过）方可合并。
5. **收尾**：合并后关闭关联 issue；`feature/*` 分支即时删除。

---

## 4. 审查清单（按层）

### 4.1 通用（所有改动）

- [ ] 编译/类型零错误；无新增 warning（CI 以 `-D warnings` 把 warning 当 error）。
- [ ] **错误处理**：外部输入、文件 IO、命令调用不裸 `unwrap()`；启动期已知安全路径（如读取自带配置）可放宽，但需注释说明。
- [ ] **隐私红线**：无任何网络外联；不采集/上传任何数据（见 doc/08 §1.4）。
- [ ] **密钥红线**：证书/密钥/令牌绝不入库；绿色版不签名决策维持（见 doc/07）。
- [ ] 不影响 doc/08 §1.3 手动测试清单既有项。

### 4.2 Rust 后端（`src-tauri`）

- [ ] **锁安全**：`Mutex` 守卫**不得**建立在临时值上跨语句借用。

  ```rust
  // ❌ 错误：State 包装是临时值，锁守卫借它，语句结束即被释放 → E0716
  let s = app.state::<Arc<Store>>().0.lock().unwrap();
  // ✅ 正确：先把 State 绑到变量拉长寿命，再取锁
  let store = app.state::<Arc<Store>>();
  let s = store.0.lock().unwrap();
  ```

- [ ] **trait 导入**：`chrono` 的时间方法需导入对应 trait —— `use chrono::{Timelike, Datelike};`（`.hour()/.minute()/.format()` 缺一不可，否则 E0599）。
- [ ] **锁粒度**：临界区尽量短；持锁期间不做 IO、不调用耗时操作、不嵌套加锁，避免死锁与卡顿。
- [ ] **跨线程**：`Arc<Mutex<AppState>>` 共享状态读写正确，无数据竞争；rdev 回调只更新时间戳、零分配。
- [ ] **平台隔离**：Windows 专属逻辑（注册表、托盘）用 `#[cfg(windows)]` 包裹，提供 `#[cfg(not(windows))]` 兜底，避免污染其他平台编译。
- [ ] **资源释放**：退出时清理托盘菜单/监听器，统一 `app.exit(0)` 收口；无后台线程泄漏。
- [ ] **单元测试**：纯逻辑改动（状态机、时段判定、跨日归档等）必须补/改 `#[cfg(test)]` 用例，且 `cargo test` 通过。

### 4.3 Vue 前端（`src`）

- [ ] **类型安全**：`npm run type-check`（`vue-tsc --noEmit`）零错误；组件 `props` / `emits` 显式类型。
- [ ] **Tauri 调用**：`invoke(...)` 有错误处理，前端不直接吞异常；失败态对用户可见（日志或提示）。
- [ ] **样式隔离**：组件 `<style scoped>`；不写死会污染全局的样式。
- [ ] **UI 控件最小化**：主窗口使用原生标题栏（缩小/关闭由系统提供），页面只保留必要控件（如暂停）；新增交互需附截图。
- [ ] **无敏感数据**：密钥/凭据不进前端代码或 `localStorage`；数据全部本地落盘（doc/08 §1.4）。

## 5. 严重级别定义

| 级别 | 含义 | 处理 |
|------|------|------|
| 🔴 **blocker** | 安全漏洞、数据丢失/损坏、竞态/死锁、破坏编译或既有契约 | 必须修，未修不合并 |
| 🟡 **suggestion** | 缺输入校验、命名/逻辑不清、重要路径无测试、明显重复代码 | 应该修，可协商 |
| 💭 **nit** | 风格/文档小瑕疵、可选命名优化 | 可选，不阻塞 |

**示例（贴合本期真实踩坑）**

> 🔴 **正确性：临时值跨语句借用（E0716）**
> `commands.rs:57` 把锁守卫绑到变量后，在下一行仍引用它，但 `State` 包装是临时值，语句结束即释放。
> **为什么**：守卫借自已销毁的临时对象，Rust 借用检查器不允许。
> **建议**：先 `let store = app.state::<Arc<Store>>();`，再从 `store.0` 取锁。

> 🟡 **正确性：trait 未导入（E0599）**
> `state.rs:285` 调用 `now.hour()/.minute()` 却未 `use chrono::Timelike;`。
> **为什么**：这两个方法是 `Timelike` trait 提供的，不在作用域就报"方法不存在"。
> **建议**：在文件顶部补充 `use chrono::{Timelike, Datelike};`。

## 6. 争议处理

- 先澄清**意图**，不默认对方写错；用问题代替断言。
- 无法达成一致 → 由 Maintainer 拍板，并把理由记入 PR 评论。
- 若发现是**标准本身有缺陷** → 回到本文档修订（文档随版本演进，见 §8）。

---

## 7. 质量门禁（CI）

- **触发**：`push` 与 `PR` 到 `main` 分支。
- **步骤**（见 `.github/workflows/ci.yml`）：
  1. 前端：`npm ci` → `npm run type-check` → `npm run build`
  2. Rust：`cargo fmt --all -- --check` → `cargo clippy --all-targets -- -D warnings` → `cargo test`
- **失败即阻断**：任一步非绿，PR 不可合并。
- **运行环境说明**：CI 在 Linux 跑"检查"（已装 webkit 等 Tauri 编译依赖）；**发布包（NSIS/MSI、绿色 EXE）仍在开发者 Windows 机器上出**，符合 doc/07 绿色版决策。

---

## 8. 度量与持续改进（轻量）

- 跟踪指标：合并前置时间（lead time）、单 PR 缺陷数、CI 通过率。
- **每季度回看本文档**：把新踩的坑固化为清单项（本期"临时值借用""trait 导入"已写入 §4.2）。

---

## 9. 配套文件

- `.github/PULL_REQUEST_TEMPLATE.md` —— PR 提交时自动出现的自检清单。
- `.github/workflows/ci.yml` —— 自动质量门禁（fmt / clippy / test / 前端类型与构建）。
