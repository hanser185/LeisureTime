## 1. 测试策略

### 1.1 单元测试（Rust 逻辑层）

重点测纯逻辑，不依赖 UI：

| 被测对象 | 用例 |
|----------|------|
| `AppState::on_activity` | 首次活动从 Idle→Working；记录 last_activity_ms |
| `AppState::tick` | Working 超休息阈值→Resting；Resting 恢复活动→Working（新片段） |
| `current_segment_ms` | 工作时长累加正确；休息中不计入 |
| `Storage` | 设置/每日数据读写往返一致；跨日文件隔离 |
| `Scheduler 判定` | 达到工作时长触发一次；稍后顺延后重新触发 |

示例（伪 Rust）：
```rust
#[test]
fn test_idle_to_working_on_first_activity() {
    let mut s = AppState::new(Settings::default(), DailyData::default());
    s.on_activity(1000);
    assert_eq!(s.user_state, UserState::Working);
}
```

### 1.2 集成测试
- 使用 rdev 模拟事件较难，建议用「注入活动」接口（`on_activity(now)`）驱动状态机，验证端到端。
- Tauri 提供 `tauri::test` 上下文，可测 command 调用与事件发射。

### 1.3 手动测试清单（QA）

- [ ] 首次键鼠活动后，Dashboard 状态变为「工作中」并开始计时。
- [ ] 静置 ≥ 5 分钟，状态变「休息中」，休息次数 +1。
- [ ] 连续工作 45 分钟，弹出 Toast（默认），含「稍后/跳过」。
- [ ] 点「稍后 5 分钟」后 5 分钟内不再提醒，之后重新判定。
- [ ] 点「跳过本次」后本片段不再提醒。
- [ ] 喝水提醒每小时（活跃时）弹一次，点「已喝水」记录并显示。
- [ ] 托盘：右键暂停/恢复、打开设置、退出；左键打开窗口。
- [ ] 关闭主窗口 → 仅最小化到托盘（进程常驻）。
- [ ] 修改设置并重启 → 配置持久化。
- [ ] 清空今日数据 → JSON 被删除/重置。
- [ ] 隐私：任务管理器确认无网络外联；数据文件无按键内容。

### 1.4 隐私合规验证
- 用 **Wireshark / Fiddler** 抓包，确认应用无任何出站连接（行为统计为零）。
- 检查 `%APPDATA%/rest-reminder/` 下文件，确认不含 PII。

## 2. 性能优化

| 目标 | 措施 |
|------|------|
| 冷启动 < 2s | Rust 轻量入口；前端首屏仅渲染 Dashboard，设置按需加载 |
| 常驻内存 < 100MB | 单 WebView + Rust 核心；避免前端轮询，改用事件驱动；图片/图标压缩 |
| 低 CPU | 调度循环 1s 粒度；rdev 回调极轻（只更新时间戳，无分配） |
| 不卡顿 | 状态读写用 `Mutex`，临界区短；落盘用异步/节流（每 30s 快照） |

---

## 3. 稳定性与内存泄漏防护

- **WebView 休眠**：计时真相放在 Rust，前端休眠不影响计时不准确。
- **线程安全**：共享状态用 `Arc<Mutex<AppState>>`，避免数据竞争。
- **资源释放**：托盘菜单、监听器在退出时正确清理；`app.exit(0)` 统一收口。
- **异常隔离**：rdev `listen` 失败仅日志，不崩溃主程序；调度线程 panic 不影响 UI。
- **长时运行**：每日 0 点跨日重置 `daily`，防止单文件无限增长；历史文件可定期清理（> 30 天）。
