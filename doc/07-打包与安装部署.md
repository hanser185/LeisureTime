# 07 · 打包与安装部署

> 需求 §6。目标：安装包 < 20 MB，便携版可用，处理签名与 SmartScreen。

---

## 1. 构建流程

### 1.1 开发构建
```bash
npm install
npm run tauri dev      # 本地调试（前端热更新 + Rust 重新编译）
```

### 1.2 生产构建（生成安装包）
```bash
npm run tauri build
```
产物位于 `src-tauri/target/release/bundle/`：
- `nsis/` → `休息提醒助手_0.1.0_x64-setup.exe`（NSIS 安装包）
- `msi/`  → `休息提醒助手_0.1.0_x64_en-US.msi`（MSI）
- `rest-reminder.exe` → 可直接运行的便携版（拷贝即用）

### 1.3 体积控制（确保 < 20 MB）
- Tauri 复用系统 WebView2，**不内嵌 Chromium**，天然小巧。
- 前端构建开启压缩：`vite.config.ts` 中 `build.minify = 'esbuild'`。
- 图标用 `.ico` 多分辨率单一文件，避免冗余资源。
- 不打包任何运行时（Rust 静态链接）。

---

## 2. 安装包类型选择

| 类型 | 优点 | 适用 |
|------|------|------|
| NSIS（推荐） | 体积小、可定制安装向导、支持静默安装 | 面向普通用户分发 |
| MSI | 企业组策略部署友好 | 公司内网批量部署 |
| 便携 EXE | 免安装、U 盘可用 | 临时/受限环境 |

> 建议同时产出 **NSIS 安装包 + 便携 EXE**，覆盖多数场景。

---

## 3. 代码签名与 SmartScreen

### 3.1 为什么需要签名
未签名 exe 在 Windows 上会触发 **SmartScreen 拦截**与「未知发布者」警告，降低用户信任与安装转化率。

### 3.2 签名方案（推荐）

| 方案 | 成本 | 说明 |
|------|------|------|
| 普通代码签名证书（OV） | 约 ¥500–1500/年 | 消除「未知发布者」，SmartScreen 仍需累积信誉 |
| 扩展验证证书（EV） | 约 ¥2000–4000/年 | **Instant SmartScreen 信誉**，下载即绿勾，需硬件 Token |
| 临时/免费 | 0 | 用 `signtool` 自签名仅本地测试，用户仍会报警告 |

### 3.3 签名命令（示例）
```bash
# 使用 Windows SDK 的 signtool
signtool sign /fd SHA256 /a /tr http://timestamp.digicert.com /td SHA256 ^
  /f mycert.pfx /p <密码> ^
  target/release/rest-reminder.exe
```
- 在 CI（GitHub Actions）中配置证书与密码（Secret），构建后自动签名。
- 启用 **RFC3161 时间戳**，证书过期后签名依然有效。

### 3.4 降低 SmartScreen 阻力的补充手段
- 使用 **EV 证书**获得即时信誉。
- 持续分发、累积下载量提升信誉评分。
- 在官网/下载页提供校验 SHA256，增强信任。
- 安装包内嵌「首次运行引导」说明，缓解用户疑虑。

## 4. 自动更新（后续可选）

- Tauri 内置 `tauri-updater`（需签名更新包 + 更新服务器）。
- 首版可不做；后续用 GitHub Releases 作为更新源。

---

## 5. 安装后行为

- 默认写入 `%LOCALAPPDATA%\rest-reminder\`（程序）与 `%APPDATA%\rest-reminder\`（数据）。
- 安装时勾选「开机自启动」（可选，默认开启，设置内可关）。
- 卸载时清理程序，但**保留用户数据**（或提供「同时删除我的数据」选项，默认不勾）。
