# 04 · 核心模块设计

> 需求 §3 的核心模块：状态检测、提醒调度、本地存储。

---

## 1. 工作状态检测模块（activity + state）

### 1.1 监听方式（隐私安全）

- 使用 `rdev` 的 `listen()` 全局钩子，**只回调「事件发生」和「事件类型/键码」**，不读取文本。
- 每次事件仅记录 `last_activity_at = now()`（毫秒时间戳），**不存储任何事件内容**。
- 另起独立线程运行监听，避免阻塞主线程。

### 1.2 状态机

```
        ┌─────────┐   首次活动     ┌──────────┐  连续无活动≥休息阈值  ┌──────────┐
        │  Idle   │ ───────────→  │ Working  │ ───────────────────→ │ Resting  │
        └─────────┘               └──────────┘                      └──────────┘
             ▲                         │  ↑                                │
             │      跨日重置            │  │ 恢复活动                        │ 恢复活动
             └────────────────────────┘  └────────────────────────────────┘
                                    （开始新工作片段）
```

| 状态 | 含义 | 进入条件 |
|------|------|----------|
| `Idle` | 今日尚未开始 / 跨日未启动 | 应用启动且今日无活动；或日期变更 |
| `Working` | 工作中 | 出现键鼠活动且未达休息阈值 |
| `Resting` | 休息中 | 连续无活动 ≥ `休息判定时长`（默认 5 min） |

### 1.3 工作片段 / 休息片段模型

```rust
/// 一个连续工作区间
struct WorkSegment { start_ms: u64, end_ms: u64, duration_sec: u64 }
/// 一个连续休息区间
struct RestSegment { start_ms: u64, end_ms: u64, duration_sec: u64 }
```

- 从 `Idle → Working`：开启 `WorkSegment`。
- `Working → Resting`：闭合 `WorkSegment`，开启 `RestSegment`，`休息次数 + 1`。
- `Resting → Working`：闭合 `RestSegment`，开启新 `WorkSegment`。

### 1.4 计时关键逻辑（tick）

每秒执行：
1. 若当前状态 `Working` 且 `now - last_activity_at ≥ 休息阈值` → 转 `Resting`。
2. 若处于 `Resting` 且 `now - last_activity_at < 休息阈值` → 转 `Working`（新片段）。
3. 累计当前工作片段时长，供 Dashboard 实时显示。

## 2. 提醒调度模块（scheduler）

### 2.1 触发条件

| 提醒类型 | 触发条件 | 防抖/冷却 |
|----------|----------|-----------|
| 休息提醒 | 当前 `Working` 且「当前片段连续时长 ≥ 工作时长阈值（45 min）」 | 同一片段只提醒一次；稍后则顺延 5/10 min 再判 |
| 喝水提醒 | 处于 `Working` 且距上次喝水提醒 ≥ 间隔（60 min） | 仅活跃时触发；用户「已喝水」后重置计时 |

### 2.2 调度循环

```text
loop every 1s:
  state.tick(now)
  if state.current_segment_duration() >= settings.work_threshold
     && !state.rest_reminder_fired_for_segment:
       emit("rest_reminder"); state.mark_rest_fired()
  if settings.water_enabled
     && state.is_working()
     && now - state.last_water_prompt >= settings.water_interval:
       emit("water_reminder"); state.last_water_prompt = now
```

### 2.3 「稍后提醒」语义

- 用户选「稍后 5 分钟」：记录 `snooze_until = now + 5min`，期间不重复提醒；到点重新进入判定。
- 「跳过本次」：清除本片段提醒标记，直到下个新工作片段再计。

## 3. 本地数据存储模块（storage）

### 3.1 方案

- **格式**：JSON 文件（轻量、可审计、零依赖）。
- **路径**：`%APPDATA%\rest-reminder\data\<YYYY-MM-DD>.json`（按日分文件，便于「今日统计」与清理历史）。
- **写入时机**：状态变更（片段闭合）、喝水记录、设置变更时落盘；调度循环内定期（如每 30s）快照。
- **读取时机**：启动加载「今日」文件；设置界面加载 `settings.json`。

### 3.2 数据结构

```json
{
  "date": "2026-08-10",
  "workSegments": [
    { "start_ms": 1691625600000, "end_ms": 1691627400000, "duration_sec": 1800 }
  ],
  "restSegments": [
    { "start_ms": 1691627400000, "end_ms": 1691627700000, "duration_sec": 300 }
  ],
  "waterIntakes": ["09:15", "10:30", "11:40"],
  "restCount": 1,
  "restRemindersTriggered": 1,
  "lastWaterPromptMs": 1691627400000
}
```

### 3.3 设置文件（与每日统计分离）

`%APPDATA%\rest-reminder\settings.json`：

```json
{
  "workThresholdMin": 45,
  "restThresholdMin": 5,
  "reminderMode": "toast",
  "waterEnabled": true,
  "waterIntervalMin": 60,
  "workHoursOnly": false,
  "workStart": "09:00",
  "workEnd": "18:00",
  "paused": false
}
```

### 3.4 隐私保障（实现层）

- `activity.rs` 永远不把事件内容写入任何结构。
- 存储文件不含任何 PII（无用户名、无按键、无截图）。
- 提供「清空今日数据」按钮（设置页），删除对应 JSON。

---

## 4. 模块协作时序（休息提醒）

```
用户连续工作 45min
   → activity.rs 持续更新 last_activity_at
   → scheduler.rs tick 发现 duration ≥ 45min
   → emit "rest_reminder" 给前端
   → 前端按 reminderMode 显示 Toast / 弹窗
   → 用户点「稍后 5min」→ invoke command → state.snooze(5)
   → 5min 后 scheduler 重新判定
```
